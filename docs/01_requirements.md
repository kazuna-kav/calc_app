# 家計簿アプリ 要件定義(草案)

## 背景・目的

既存の家計簿サービス(マネーフォワード等)は口座連携の精度や、金融データを外部サービスに
預けること自体への信用に不安がある。そこで **自分の手で記録し、データを自分の端末の中だけで
管理できる** シンプルな家計簿アプリを作る。

### 基本方針

| 方針 | 内容 |
|---|---|
| ローカルファースト | データはブラウザの localStorage のみに保存。外部送信は一切しない |
| ゼロ依存 | サーバー不要・ビルド不要・外部 CDN 不要。`index.html` を開くだけで動く |
| 手入力前提 | 口座連携はしない。入力の手間を最小化する UI で補う |
| データは持ち出せる | CSV / JSON でいつでもエクスポート・インポートできる(ロックインしない) |

## 機能要件

### 必須(MUST)

- **収支の記録**: 支出 / 収入を記録できる
  - 日付(デフォルトは今日)
  - 金額(円・整数)
  - カテゴリ(プリセットから選択)
  - 名目(自由記述のメモ。例:「スーパーで食材」)
  - **支払い方法**(何から使ったか): 現金 / クレジットカード / Suica / PayPay / 銀行口座 / その他
- **一覧表示**: 記録した明細を月ごとに一覧できる。編集・削除ができる
- **グラフ表示**:
  - 月ごとの収入・支出の推移(直近6ヶ月)
  - 当月の支出カテゴリ内訳
  - 当月の支払い方法別の支出内訳
- **月のサマリー**: 当月の収入合計・支出合計・収支(残り)を常に確認できる

### あったほうがよい(SHOULD)

- 一覧の絞り込み(カテゴリ / 支払い方法 / キーワード)
- CSV / JSON エクスポート・インポート(バックアップ・乗り換え用)
- ダークモード対応
- スマホでも使えるレスポンシブ表示

### やらないこと(WON'T)

- 口座・カード連携(信用できない外部連携はしない、という動機そのものなので)
- アカウント・ログイン機能(端末ローカルで完結)
- クラウド同期(必要になったらエクスポート/インポートで代替)

## カテゴリ設計

### 支出カテゴリ

食費 / 日用品 / 交通費 / 住居 / 水道光熱 / 通信 / 医療・健康 / 交際費 / 趣味・娯楽 / 衣服・美容 / その他

### 収入カテゴリ

給与 / 賞与 / 副業 / 臨時収入 / その他

### 支払い方法(支払い元)

現金 / クレジットカード / Suica / PayPay / 銀行口座 / その他

> カテゴリ・支払い方法はコード上で一元定義し、将来のカスタマイズ機能追加に備える。

## 非機能要件

| 項目 | 要件 |
|---|---|
| 動作環境 | モダンブラウザ(Chrome / Edge / Safari / Firefox)。file:// で直接開いても動くこと |
| データ保存 | localStorage。スキーマにバージョンを持たせ、将来の移行に備える |
| プライバシー | 外部への通信ゼロ(fetch / CDN / アナリティクス一切なし) |
| 表示速度 | 数千件の明細でも一覧・グラフが体感遅延なく描画できること |
| アクセシビリティ | フォームはラベル付き、グラフはツールチップ+数値の直接表示で色だけに依存しない |

## 画面構成(3タブ)

1. **入力** — 収支入力フォーム(最頻の操作なので初期表示)
2. **一覧** — 月ごとの明細一覧、絞り込み、編集・削除
3. **グラフ** — 月次推移・カテゴリ内訳・支払い方法内訳

詳細は [02_design.md](./02_design.md) を参照。
