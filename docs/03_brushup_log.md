# ブラッシュアップログ

初版から3回のブラッシュアップで何をどう改善したかの記録。

## v0.1 初版

**ゴール: まず記録できて、消えないこと。**

- 要件定義([01_requirements.md](./01_requirements.md))と設計書([02_design.md](./02_design.md))を作成
- 収支入力フォーム(日付・金額・カテゴリ・支払い方法・名目)
- 月ごとの明細一覧・削除・月次サマリー(収入/支出/収支)・月送り
- localStorage 永続化(スキーマバージョン付き)

## v0.2 ブラッシュアップ① — 「見える化」

**ゴール: 記録したデータから傾向が読み取れること。**

| 追加 | 内容 |
|---|---|
| 月次推移グラフ | 直近6ヶ月の収入・支出を縦棒2系列で。凡例常設・ホバーで両系列の値を表示 |
| 支出カテゴリ内訳 | 単色横棒・金額降順・棒の先端に金額を直接表示 |
| 支払い方法別支出 | 同上。Suica / PayPay / クレカ など「何から使ったか」を可視化 |

設計判断:

- **外部チャートライブラリを使わず SVG 自前描画**。外部通信ゼロ・依存ゼロの方針を貫くため
- 配色はライト/ダーク両面で検証済みのパレット(色覚多様性 ΔE・コントラスト比のチェックを
  スクリプトで検証してから採用)
- 値は「グラフ上の直接ラベル+ツールチップ」の二重化で、色が判別できなくても読める

## v0.3 ブラッシュアップ② — 「直せる・持ち出せる」

**ゴール: 打ち間違いを直せること、データを人質に取らないこと。**

| 追加 | 内容 |
|---|---|
| 明細の編集 | 一覧の ✏️ からフォームに読み込み、更新・キャンセル |
| 絞り込み | カテゴリ / 支払い方法 / 名目キーワードで一覧をフィルタ |
| エクスポート | 全期間を CSV(BOM付き・Excelでそのまま開ける)/ JSON でダウンロード |
| インポート | CSV / JSON を追記取り込み。行単位でバリデーションし、同一IDはスキップして件数を報告 |

## v0.4 ブラッシュアップ③ — 「毎日使える道具に」

**ゴール: スマホでも夜でも気持ちよく使えること。**

| 追加 | 内容 |
|---|---|
| ダークモード | OS設定に自動追従(`prefers-color-scheme`)。グラフの色もダーク面向けに調整 |
| レスポンシブ | スマホ幅(〜480px)でヘッダー・ボタン・絞り込みバーを最適化 |
| バリデーション強化 | 金額上限(1億円)で桁の打ち間違いを防止、日付形式チェック |
| ドキュメント整備 | 本ログの作成、README・要件定義の実装状況を最終化 |

## v0.5 — iPhone 対応(PWA化+ショートカット連携)

**ゴール: iPhoneのホーム画面から「アプリ」として使え、2タップで記録できること。**

| 追加 | 内容 |
|---|---|
| PWA化 | manifest・アイコン・iOS用メタタグ・Service Worker(オフライン起動) |
| クイック入力URL | `?add=1&amount=…&category=…` で即登録 / 金額なしなら事前入力。処理後にクエリを消して二重登録防止 |
| Pages 配信 | GitHub Pages への自動デプロイワークフロー(要 Settings で有効化) |
| 手順書 | [04_ios_pwa.md](./04_ios_pwa.md) — ホーム画面追加・ショートカット作成・ロック画面/背面タップ活用 |

設計判断: iOS ウィジェットはテキスト入力を受け付けないため、ネイティブ化ではなく
「PWA+ショートカットのクイック入力URL」で同等の体験を先に実現。
本物の WidgetKit ウィジェットが必要になった時点で Capacitor 化を検討する。
